# 拾页 Agent 接入包 1.3.0

适配拾页 macOS 1.9.x / 1.10.x，实际验收版本为 1.10.0；日期见发行说明。本包提供跨 Agent 操作说明、分类路径、标签和检索调用工具。

## 今后如何给 Agent 下任务

把同目录的 `给Agent的任务开头.txt` 放在任务开头，再说明最终文件、分类目标和本次允许的读取范围。最简写法：

> 先读取 `/path/to/agent-kit/AGENTS.md`，再把本次最终成品加入拾页，完成应用内分类并验证正文检索。只整理最终成品，不删除旧记录。

也可以把这条入口放进某个项目已有的 Agent 规则中，保留该项目其他规则。**不能保证不同 Agent 会自动发现此处的 AGENTS.md**；首次使用应明确给出路径，或把文件作为附件交给它。能读本地文件、执行命令的 Agent 可以用本工具；仅支持 MCP 的 Agent 可以查询，但当前拾页 MCP 没有写入工具。

文件用途：

| 文件 | 用途 |
|---|---|
| AGENTS.md | 直接给 Agent 阅读的完整操作规范 |
| shiyue_agent.py | 调用现有 HTTP 接口，查询文件、添加分类/标签、检索和读回 |
| 接口契约.json | 便于程序读取的入口、参数、回执和权限约定 |
| 给Agent的任务开头.txt | 可直接复制的任务前缀 |
| 验证结果.json | 本接入包的测试结果与验收边界 |

除 self-test 外，HTTP 命令需要拾页正在运行。使用应用自带 Python，不需安装依赖。令牌由官方 Client 本地读取，不写进任务提示词。工具退出码 0 表示命令成功，2 表示错误；入库是否完成仍以官方 CLI 回执为准。

## 拾页与直接找本地文件怎么选

**拾页主要提供统一的正文索引和可追溯引用；已知路径的操作仍直接访问文件。** 两种方式配合最实用。

| 任务 | 更合适的入口 | 原因与边界 |
|---|---|---|
| 已知文件路径，编辑、排版、构建或检查最新字节 | 直接访问原件 | 无须经过索引，读到磁盘现状；拾页索引可能尚未更新 |
| 不知道文件在哪，只记得书里一个术语 | 先搜索拾页 | 已提取的 Word、HTML、PDF 等可统一查正文，不必每次重新解析各文件 |
| 比较多本书、按段落给出出处 | 拾页检索 → 段落读回 | 带文件 ID、内容 SHA、提取版本和固定段落引用；须核对实际证据 |
| 新文件、未入库文件，或语义相近但关键词不同 | 直接查授权目录，或换检索词 | 当前主要是词项检索，不能保证理解任意问法；搜不到不能推出不存在 |
| 图片、扫描页、复杂表格和页面布局 | 打开原件，按需 OCR/专用读取 | 索引中的纯文本不是完整视觉内容，text_indexed=true 也不证明版面解析完整 |
| 外置盘暂时离线 | 先读拾页已保存的提取正文 | 有索引正文时仍可查；若未托管/备份原件，无法因此恢复原始文件 |

推荐工作顺序：**先查拾页定位证据 → 需要编辑或版式时打开原件 → 完成修订后重新提交索引 → 复核分类与检索。** 已知确切路径时直接从第二步开始。

这不是速度测试结论。59 份资料中，直接按路径或文件名查找也可能很快；拾页的主要收益是减少重复解析、统一返回正文与出处、集中维护分类和读取范围。它不会让 Agent 自动获得整个磁盘，也不会自动使所有问法命中。多个载体的同一本书不能算作多份独立证据。

只读 MCP 的 profile 限制拾页工具返回范围，不是操作系统级文件隔离；拥有文件系统权限的 Agent 仍能直接读取其权限内文件。本地索引本身不上传，但云端 Agent 可能将读到的段落发给模型。管理 HTTP 会话是所有者权限，应用内读写接口不能当作受限只读凭据交付。

## 迁移与限制

接入包只包含代码和说明，不保存用户资料与令牌。换机器可复制本目录，调整应用/资料库路径；真实个人库及外部原件仍按拾页自身备份、迁移流程保管。旧 macOS 发布包和 Android 版本保留。

归类工具仅新增分类归属并合并标签；底层接口是多次请求，非整体原子操作，没有同文件标签的跨客户端并发保护。出现部分失败会返回已完成步骤，复核后重试。同一批资料不要由多个 Agent 同时修改元数据。

本包验证了独立资料库的实际 HTTP/CLI 操作与真实资料库只读查询；没有代替 WorkBuddy 实际执行新一轮任务，也没有声称其他 Agent 已自动读取规范。

## 9 级分类

从顶级开始计算 1–9 级。应用内选择分类后点“新建子分类”，也可在新建窗口选择上级。父分类默认汇总全部下级资料，关闭“包含子分类”可只看直接归入本级的文件。“移动分类”会移动整条分支，系统检查重名、循环及 9 级限制。

Agent 通过 `--collection-path '["经学","易学","周易"]'` 按完整路径归类，或通过 `--collection-id` 指定既有子分类。按名称指定的 `--collection` 用于顶级分类。当前管理方式和验证结果以 AGENTS.md 与验证结果.json 为准。


## 1.2 新增能力

search 支持服务端分类/精确标签筛选，默认含子分类，并返回完整归属；`--include-paths` 追加文件位置。prefer 可保存经确认的优先版本关联，保留旧文件与引用。写入前检查 1.9.x / 1.10.x 和所需能力，未知版本转为只读。

便携自检：用指定 App 的 Python 执行 `shiyue_agent.py --app '/实际应用.app' self-test`。完整复制本目录，包括 self_test.py、tests/ 和 checksums.json；校验失败先检查文件是否被修改。自检仅运行临时库，不连接个人库，也不需要开发项目目录。checksums.json 检查包内文件是否一致，不是外部机构签名。

扫描界面新增规则、预览理由、确认入库和批次撤销。规则只按文件信息匹配；用户需先创建目标分类。规则/优先关系随完整资料库备份保留，旧格式单独资料包不包含这些新增关系。现有个人分类不会因升级自动重排或重新归类。
